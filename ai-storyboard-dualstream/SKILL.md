# AI 影视分镜双流编译器 V8

## 开始前

1. 完整阅读 [references/v8-runtime-rules.md](references/v8-runtime-rules.md)。它是规则、阈值、例外、硬锁和输出格式的唯一裁决源。
2. 若输入含参考图，先检查所有参考图；只继承稳定视觉信息，不继承静态姿势。
3. 识别工作模式：完整剧本、分段续写、局部修改，或用户明确要求的 CSV 九宫格。
4. 默认采用 3D 国漫与 16:9 横屏；用户明确指定画风、平台、画幅或参考时覆盖默认值。

## 执行原则

- 严格按“用户本轮要求 → 原剧情与原台词 → 安全合规 → 连续性与物理状态 → 时长和格式 → 参考资产 → 影视表达 → 默认审美”处理冲突。
- 不新增、删除、改写、概括、合并或调序剧情、台词、OS、明确旁白、人物关系、事件结果和动作顺序。
- 只补足原动作的方向、起势、过程、受力、落点、材质反应、环境反馈和剪辑承接；不创造新事件、新能力或新世界观。
- 先通过 P0 硬闸门，再按当前剧情加载表演、声音、动作、镜头、灯光、景深、特效和高级运镜。不要把未触发的词库复制进输出。
- 只写观众能看到或听到的内容；纯叙事优先视觉化，不自行添加旁白、字幕、BGM、UI、路人、特效或环境破坏。

## 双流编译

### 视觉资产流

只为本段实际出现或首次需要建立的角色、动物、生物、关键道具和场景生成中文文生图提示词。为每个资产固定核心识别特征；后续逐字复用。视频正文不重复静态外貌，除非外观变化本身属于剧情动作。

### 动态分镜流

1. 建立原文覆盖清单、角色固定声线资产、角色表演指纹、场景空间锚点、180 度轴线和场景光线母状态。
2. 分配动作、台词、OS、视线和反应。每镜只设一个主要动作主体，且默认只保留一个核心高复杂度变量与一个辅助变量。
3. 对每句有声内容做静默计时与承载校验。可运行 `scripts/estimate_dialogue.py` 辅助估算；数字、英文、缩写及停顿仍须按实际读法复核。
4. 长台词默认跨镜连续说：预计超过 3.2 秒时规划镜头组，超过 3.8 秒时必须拆镜，超过 4.5 秒时必须拆镜或顺延视频编号。只有用户明确要求一镜到底时例外。
5. 让每次切镜新增信息、危险、情绪、空间、受力结果或关系变化。默认每个 10 秒编号 3–5 镜；镜头总时长精确相加且不超过 10.0 秒。
6. 逐镜继承姿势、位置、方向、速度、视线、道具、伤势、破坏、烟尘、特效残留与光线。不得用“同上”“接前文”替代完整状态。
7. 按剧情能量 L0–L4 选择景别、角度、构图、焦点、运镜和灯光。高级运镜必须有动机与落点，不能牺牲方位、表演、口型、动作结果或关键信息。

## 声音硬锁

- 显性台词：角色开口并口型同步，原文逐字保留。
- 内心 OS：非现场内心声；角色全程闭口，不做发声口型，并写明画面承载。
- 每句台词、画外继续说、明确旁白和 OS 前都完整写：`配音指令：角色名|固定声线类型|当前表演状态|声音执行参数`。
- 固定声线类型保持角色一致；临时情绪、重伤、哭腔、喘息等写入表演状态或执行参数，不冒充固定声线。
- 长台词跨镜时使用“继续说”“画外继续说”“接上镜台词”；每段原文只出现一次，不漏字、不重复、不改序。
- 时长不足时，先压缩非必要运镜与装饰描述，再拆镜或顺延编号；绝不提速吞字或删除内容。

## 输出

可在代码块外给出极短公开预检，只写关键词、项目类型、制作形态、预计时长/编号、触发模块与冲突裁决结论，不输出内部推理。

除非用户明确缩减交付，依次输出：

1. 导演执行表；
2. 视觉资产提示词；
3. 纯视频生成提示词；
4. 仅在明确要求时输出 CSV 九宫格。

每个视频编号单独使用一个 `plaintext` 代码块，并完整写出【项目规格】【全局视觉】【场景与连续状态】【光线】【出场人物】及逐镜头分解。逐字保留全局硬锁：

`画面无字幕、无水印、无无关文字；非剧情所需时不出现游戏UI。禁止生成背景音乐，仅保留剧本对白、明确OS和必要物理音效。`

镜头项至少包含时长、景别、角度、运镜及动机、构图、画面、表演与互动、声音与台词。不要把内部承载数值或“通过/失败”标记写进最终视频提示词。

## 交付闸门

输出前按 [references/v8-runtime-rules.md](references/v8-runtime-rules.md) 的“输出前校验”逐项检查所有必检项与已触发条件项。任一核心闸门失败，回退重分配、拆镜或顺延，直至真实通过。
